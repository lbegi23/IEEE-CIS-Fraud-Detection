# IEEE-CIS-Fraud-Detection

## პროექტის აღწერა

ეს პროექტი წარმოადგენს Kaggle-ის IEEE-CIS Fraud Detection კონკურსის ამოხსნას. მიზანი იყო საბანკო ტრანზაქციების კლასიფიკაცია — თაღლითური თუ ლეგიტიმური — სხვადასხვა მანქანური სწავლების მოდელების გამოყენებით. ექსპერიმენტების დალოგვა განხორციელდა MLflow-ისა და DagsHub-ის საშუალებით.

## მონაცემები

მონაცემები შედგება ორი ფაილისგან:

- `train_transaction.csv` — ტრანზაქციების მონაცემები
- `train_identity.csv` — მომხმარებლის პირადობის მონაცემები

ორივე ფაილი გაერთიანდა `TransactionID`-ის მიხედვით left join-ით, ვინაიდან ტრანზაქციების დაახლოებით 75%-ს პირადობის მონაცემები არ გააჩნდა. შეერთების შემდეგ მონაცემთა ნაკრები შეიცავდა 590,540 სტრიქონს და 434 სვეტს. კლასების დისბალანსი მნიშვნელოვანი იყო — თაღლითური ტრანზაქციები მხოლოდ 3.5%-ს შეადგენდა.

## მონაცემთა გაყოფა

მონაცემები დაიყო სამ ნაწილად:

- **Train set:** 70% — მოდელის სწავლებისთვის
- **Validation set:** 15% — ჰიპერპარამეტრების ტუნინგისთვის
- **Test set:** 15% — საბოლოო შეფასებისთვის

გაყოფა განხორციელდა ისე რომ კლასების პროპორცია ყველა ნაწილში ერთნაირი ყოფილიყო.

## მონაცემთა გასუფთავება

თითოეულ ნოუთბუქში შემდეგი ნაბიჯები განხორციელდა:

- წაიშალა 50%-ზე მეტი გამოტოვებული მნიშვნელობის მქონე სვეტები (214 სვეტი)
- წაიშალა მაღალი კარდინალობის კატეგორიული სვეტები: `DeviceInfo`, `id_33`, `id_31`, `id_30`

## ფიჩერ ინჟინერია

ყველა მოდელისთვის შეიქმნა შემდეგი ახალი ფიჩერები:

- `TransactionAmt_log` — ტრანზაქციის თანხის ლოგარითმი (გადახრის შესამცირებლად)
- `TransactionAmt_cents` — ტრანზაქციის თანხის ცენტების კომპონენტი (თაღლითები ხშირად იყენებენ მრგვალ რიცხვებს)
- `hour` — ტრანზაქციის საათი (დღე-ღამის პერიოდი)
- `day` — კვირის დღე

## ფიჩერების შერჩევა

- **Logistic Regression:** გამოყენებულ იქნა `VarianceThreshold` — დაბალი ვარიაციის მქონე სვეტები წაიშალა (22 სვეტი). დარჩა 200 ფიჩერი.
- **Random Forest და XGBoost:** გამოყენებულ იქნა feature importance — ნულოვანი მნიშვნელობის მქონე ფიჩერები წაიშალა.

## კლასების დისბალანსი

გამოცდილ იქნა ორი მიდგომა:

1. `class_weight='balanced'` / `scale_pos_weight` — მოდელის წონების კორექტირება
2. `RandomUnderSampler` — majority კლასის შემცირება

ყველა მოდელში undersampling-მა შედეგი გააუარესა, ამიტომ საბოლოოდ გამოყენებულ იქნა წონების კორექტირება.

## მოდელები და შედეგები

თითოეული მოდელი ცალკე ნოუთბუქსა და MLflow ექსპერიმენტში განხორციელდა.

| მოდელი | Val AUC | Test AUC |
|---|---|---|
| Logistic Regression | 0.8407 | 0.8393 |
| Random Forest | 0.9152 | 0.9162 |
| XGBoost (baseline) | 0.9298 | 0.9344 |
| **XGBoost (tuned)** | **0.9591** | **0.9607** |

### Logistic Regression (`model-experiment-logistic-regression.ipynb`)
მარტივი ბაზისური მოდელი. გამოყენებულ იქნა `StandardScaler` და `OrdinalEncoder`. მოდელმა მიაღწია 0.8393 AUC-ს test set-ზე.

### Random Forest (`model-experiment-random_forest.ipynb`)
არ საჭიროებს სქეილინგს. გამოყენებულ იქნა `class_weight='balanced'`. მიაღწია 0.9162 AUC-ს.

### XGBoost (`model-experiment-xgboost.ipynb`)
საუკეთესო მოდელი. ჰიპერპარამეტრების ტუნინგი განხორციელდა `RandomizedSearchCV`-ით (10 კომბინაცია, 3-fold CV). საუკეთესო პარამეტრები:

- `n_estimators`: 300
- `max_depth`: 8
- `learning_rate`: 0.1
- `subsample`: 0.8
- `colsample_bytree`: 1.0

საბოლოოდ მოდელი გატარდა `sklearn Pipeline`-ში და დარეგისტრირდა Model Registry-ში სახელით `xgboost-tuned-pipeline`.

## Inference (`model-inference.ipynb`)

საუკეთესო პაიპლაინი ჩამოიტვირთა MLflow Model Registry-დან და გამოყენებულ იქნა Kaggle-ის ტესტ სეტზე. შედეგი შენახულია `submission.csv` ფაილში.
